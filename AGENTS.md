# HQ Office

A local command centre for people who run AI coding agents in herdr: a 3D office in the manner of late-90s life-sim games where every lane (an AI agent working one task) is a worker at a desk in its team's room, plus the panel where the owner answers HQ's questions. It runs as a herdr plugin or as `bun server.ts`, at http://127.0.0.1:4747 by default.

If `AGENTS.local.md` exists next to this file, read it too: it holds the rules of this particular installation (how the server is run and restarted, who to report to). It is gitignored and never published.

- `server.ts`, `public/`, `src/`: the server and the page, one file per concern (see the map below).
- `hud.ts`: HQ's CLI (`hud` when linked onto PATH, or `bun hud.ts`).
- `src/lane-tree.ts`: the lane tree's depth, path, level names and `hud tree` text (shared by the server and the CLI).
- `src/hq-guide.ts`: the HQ guide (how HQ reaches the owner: through the HUD) and its one-line reminder. The one copy: `hud guide`, the plugin's greet and the server's messages to HQ all use it.
- `src/server/secrets.ts`: the secret drop. Values in server memory only; see the README. `src/server/secret-ledger.ts` keeps their names (never values) so a restart can say what it lost; `src/secret-handover.ts` is the plugin's half of the handover that carries values across a planned restart.
- `bin/hud-plugin.ts`, `herdr-plugin.toml`: the herdr plugin (actions, the status pane, and `greet` on `pane.agent_detected`); `bin/service.ts` (service mode: launchd, systemd), `bin/hud-command.ts` (installs `hud`). Their tests (`test/plugin/`) use a fake home and `test/fake-service.ts` for launchctl and systemctl: never run the real ones from a test.

Rules for anyone changing it:
- The stack and the reader are the point. A change to the office must never make an open question harder to see or answer.
- Never touch `hud.db` by hand and never delete it: it holds the owner's answers.
- After a change under src/server/ (or server.ts), restart the server (the plugin's reload action, or however `AGENTS.local.md` says this installation runs it). The page's files (public/, src/client/) are read on every request; a reload is enough, and open pages reload themselves.
- Original art only: every model, texture and poster is made in this repo, in the spirit of late-90s life-sim games; never copy models, sprites, textures, names, logos or UI from a real game (no plumbob-like markers).
- A secret value must never reach `hud.db`, a log, a listing or the page's markup or storage. `bun test` greps for it.
- Code, comments and docs name no real person, machine or service label: say "the owner", "this machine". The owner's name comes from `HUD_OWNER` at run time.
- Tests start their own servers on spare ports with throwaway data dirs. Never point a test or `hud` at a server that holds real answers.

## Map

No build step: the browser loads `src/client` as it is, Bun runs `src/server` as it is. Each file's first line says
what it is for. `docs/structure.md` explains the layout and its trade-offs.

- `server.ts`: the entry, one import of `src/server/main.ts`, so the service, the plugin and the tests still run `bun server.ts`.
- `public/index.html`: the page shell (head, markup). The server adds every stylesheet and every feature folder when it serves it.
- `src/client/main.js`: loads the built-in areas in their original order.
- `src/client/core/`: shared by every area: `state.js` (S, CONFIG), `net.js` (post), `bus.js` (events), `boot.js` (load, stream, autoreload), `format.js`, `text.js`, `dom.js`, `clicks.js`, `status.js`, `markdown.js` (markdown as safe HTML: questions, updates, rooms); `base.css`, `controls.css`, `layout.css`, `markdown.css` (markdown and folds).
- `src/client/world/`: the page's side of the 3D office, its contract with the rest of the page: `index.js` (the feature entry: mounts the office from `office-view/view.js` on `<canvas id="world">` with a dynamic import, so `?world=off` never fetches three.js or the engine; fits it right of the stack, right of the open reader and below the top bar; drives it from the bus `state`, `theme`, `settings`, `select` and `stage` events; Q/E turn a quarter, 0 fits, and the turn and fit buttons do the same; exposes a read-only `window.__world` for tests), `api.js` (the one door for other areas: `THREE`, `onFrame`, `deskAnchor`, `project`, `addToWorld`; bus events `world:ready`, `world:select`, `world:hover`, `world:layout`), `world.css` (the turn and fit buttons).
- `src/client/office/`: the office on the `@hq/world` engine (`docs/engine/rfc.md`, 12), pure; the page draws it through `office-view/`: `layout.js` (team rooms of four desks grouped by the lane tree, stable desks, walls, doors, growth stages counted in rooms), `plan.js` (`officeDoc`: lanes to a world doc, with stable ids `desk:<lane>`, `chair:<lane>`, `lane:<lane>`), `furnish.js` (each room's furniture in its own frame), `acts.js` (the act per status, a table), `japandi/` (the office's pack, D15: one file per piece, floors, the banded plaster, the noren doorway and the window; colours for light and dark in `japandi/look/palette.js`, round shapes in `japandi/look/shapes.js`; `bun packages/world/tools/check.ts src/client/office/japandi/index.js`), `outside/` (the land round the office as the engine's scenery, pure: `gen.js` and `city.js` generate the valley or the town from a seed, `scenery.js` (`outsideScenery(layout, { mode, seed })`) turns it into pieces, fields, ribbons and movers, `garden.js` lays the garden on the lot, `land/` is their pack, one file per piece, colours in `land/look/palette.js`), `lab/` (generated offices for the world lab: `bun packages/world/tools/serve.ts`, then `/?world=/src/client/office/lab/office-12.world.js`, with `&lanes=N`, `&status=S`, `&outside=nature|city|off` and `&seed=S`; `office-4.world.js` for one team, `office-24.world.js` for 24 lanes, `office-12-nature.world.js` and `office-12-city.world.js` with the land round them; `bun packages/world/tools/proof.ts --only perf --worlds ...` counts their draw calls and triangles). Tested headless in `test/client/office-plan.test.ts` and `test/client/office-outside.test.ts`; Bun finds `@hq/world` through `tsconfig.json` paths, the browser through the import map.
- `src/client/office-view/`: the office on the engine in the page (D18). `view.js` (`mountOffice`, what `world/index.js` mounts: builds the doc with `officeDoc` and calls `world.apply` on each state; binds `world/api.js` to the engine's anchors, projection and attach; the selection ring; a pace system for PERFORMANCE; the land round it from the OUTSIDE setting, as the engine's scenery (`office/outside/scenery.js`), with `setIdleFps` from PERFORMANCE), `balls.js` (the subagent balls round each desk), `lamps.js` (each room's lamp at night, lit while one of its lanes is active), `marks.js` (a status lantern on each desk and a badge over a worker the owner should look at), `size.js` (the one scale rule for small things drawn over the office). ## Working in parallel (lanes)

- Before starting, a lane names the files it will touch. Two lanes never touch the same file at the same time.
- A lane owns its feature's folder: `src/client/<feature>/`, `src/server/<feature>.ts`, `src/server/routes/<feature>.ts`, `src/server/schema/<table>.sql`, `test/*/<feature>.test.ts`.
- Shared files change only in a lane that says so up front, as a small change of its own merged before the work that needs it: `src/client/core/*` (contracts: state, net, bus, status, base styles, layout), `src/client/main.js`, `src/client/world/api.js`, `src/client/office/layout.js`, `src/client/office/plan.js`, `src/server/main.ts`, `router.ts`, `page.ts`, `db.ts`, `config.ts`, `push.ts`, `state.ts`, `public/index.html`.
- Hook in, do not reach in: listen on `core/bus.js` instead of adding a call to another area's render function; use `addStatePart` instead of editing `state()`; add a route file instead of editing another lane's.
- Do not reformat, rename or reorder code in files you do not own.
- A change to the office must keep `bun test --timeout 90000 test/client/world.test.ts` passing (needs Chrome; WebGL runs on SwiftShader).
- `bun test` passes before every commit; `test/client/modules.test.ts` catches a broken import before a browser does.
- Work on the panels does not need the 3D office. Open `/?world=off`: the office is never imported, so neither three.js nor the engine is fetched. In a test, start Chrome with `startChrome()` and no `webgl`, and load `/?world=off`. Run `bun run test:hud`. Only office work needs `bun run test:world` (it runs the tests that use WebGL). Before a commit, `bun test` still runs both.

## How to add

- **A page feature or panel**: create `src/client/<name>/index.js` (and `<name>.css`). The page loads it after the built-in areas, no other file changes. Import what you read (`S` from `core/state.js`, `post` from `core/net.js`, `$` from `core/dom.js`) and render from the bus: `on("state", (S) => render())`. A panel inserts its own element (for example into `.dock` or after the stack); it must never push an open question out of view.
- **Something drawn in or over the office**: `onFrame((now, dt) => ...)`, `deskAnchor(lane)` and `project(v)` from `src/client/world/api.js` (HTML over a desk), or `addToWorld(obj, lane)` for a three.js object at a lane's desk; listen for `world:ready` before using them.
- **A route**: add `{ method, path | prefix | pattern, handle }` to `src/server/routes/<resource>.ts`, or add the file. GET handlers return a Response; POST handlers get `{ body, m }` and return the JSON reply (nothing means `{ ok: true }`); writes are bumped for you.
- **A table**: `src/server/schema/<table>.sql` with `CREATE TABLE IF NOT EXISTS`. Changing an existing table is a migration: ask HQ first.
- **Server logic and state**: `src/server/<name>.ts`, imported by its route file; `addStatePart("<name>", () => value)` from `state.ts` puts it in `/api/state` as `S.<name>`. The function gets the state built so far (`(s) => ...`): build on `s.open` or `s.rooms` instead of querying them again.

## Releasing

Every public release goes through `scripts/release.ts`; nothing is copied to the public repo by hand.

1. Add the version's section to `CHANGELOG.md` (`## [X.Y.Z] - YYYY-MM-DD`, Keep a Changelog style, written for the people who use the plugin), and bump `version` in `herdr-plugin.toml` and `package.json`. Commit.
2. `bun scripts/release.ts X.Y.Z` exports the tracked tree of HEAD (`--ref R` for another) with `git archive`, leaves out `AGENTS.local.md` and whatever `.release-exclude` lists, fails on any line matching a pattern in `.release-denylist` (printing file and line), runs `bun install` and `bun test` on the export, then copies it into a local clone of the public repo (`--public DIR`, default `../hq-office-public`, cloned from `--remote URL` when missing), commits `release: vX.Y.Z` with the changelog section and tags `vX.Y.Z`. It stops there and prints what it would push.
3. Read the commit in the clone. Then run it again with `--push`: it pushes main and the tag and creates the GitHub release with the changelog section as its notes.

`.release-exclude` (paths, one per line, `#` comments) and `.release-denylist` (one regular expression per line, matched case-insensitively; a line `!TEXT` allows that exact text) are gitignored: each installation keeps its own. Without a denylist the script refuses to run.
